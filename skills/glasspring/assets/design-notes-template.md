# design-notes.md 标准模板

> 用途：每次 GP 运行的设计说明**统一格式**——使跨 run 对比、审计回溯、用户终审的成本降到最低。
> 适应：所有 Glasspring 产出。允许增删节但**九节序号不可换**。
> **格式约束**：节标题必须用 `## §N` 格式（如 `## §0 · 路由与默认值`）——`verify_output.py` 机械检查按此模式匹配（`## 0` 或 `# §0` 也可，但前缀 `#` 不可省略且编号必须有序）。

## §0 · 路由与默认值

- 四维路由判定（类型×领域×平台×栈）
- 未指定维度的默认值声明
- 参考文件读取清单与预算取舍理由
- **BEFORE 副本纯证据律**（superdesign 895★ 深读 2026-10-24）：restyle 先做现状页的**像素级 HTML 副本**（按路由命名存 `.restyle/` 复用）——副本内**禁止任何设计与改进、禁加占位节**（"DO NOT design or improve anything in the replica"）；副本是证据基线，改进发生在迭代稿上；改动既有代码前先问（同意制）
- **多页持久化分层**（ui-ux-pro-max MASTER.md 模式 2026-10-24）：多页站点设全局 MASTER（token/组件基线）+ 每页覆写文件**只写偏差**（"only deviations from Master"）；构建某页先查页覆写、无则用 MASTER；既有 MASTER 重跑不静默覆盖（--force 需用户明示）——design-notes 是 MASTER 的一次性形态，多页工程升此模式
- **流程重量按宪法选**（Kiro spec 流对照 2026-10-23）：本模板=集成 oneshot 流（计划与构建一体，用户可纠错点内嵌）；高风险规划类项目可升 Kiro 三门 spec 流（requirements(EARS)→design→tasks，每阶段显式批准门）——重量随代价，不随仪式
- **混合项目定序**（HachikoJ/ui-ux-design-router 1★ 深读 2026-10-24）：品牌+产品混合项目**固定先品牌后产品**——品牌系统是产品的 token 上游，反序必返工
- **品牌敬畏律**（imagegen brandkit 交叉 2026-10-22）：项目已有品牌资产时**原样复用**——"Do not invent replacements or reinterpret the logo"；restyle 是换语境不是换身份；灵感参照只取质量与节奏，永不复制 logo/命名/构图/slogan
- **三 dial 调参**（taste-skill legacy 机制 2026-10-22；用户可显式给值 1-10，默认从选中包性格轴推导）：①**方差** 1-3 对称网格 / 4-7 错位重叠+异形比例 / 8-10 非对称+大片空区（>4 禁居中 hero）②**动效** 1-3 静态仅 hover/active / 4-7 流畅 CSS（transform+opacity） / 8-10 编排级（滚动叙事/视差）③**密度** 1-3 美术馆（巨空） / 4-7 日常应用 / 8-10 座舱（小 padding、卡片禁用改 1px 线分组、数字强制 mono——与 23 屏基线互证）。本页三 dial 取值：方差 N / 动效 N / 密度 N + 理由

## §1 · 方向取舍

- 发牌 N 个方向（每个：名称/布局/字族/色系/图像）；发牌前用**九个创意引擎**检视题材（taste-skill 247 站研究 2026-10-22 增补为九）：产品自证 / 页面即题材世界的器物 / 名字即主角 / 单一 motif 驱动全页 / 装扮成另一品类 / 场所承载（一整屏大景+底边名字）/ 固定舞台（标题钉住内容换）/ 一节一色（色场作章节）/ 极端克制（小标题+微型活演示贯彻到底）
- **方向承诺三律**（taste-skill draw.mjs 机制 2026-10-22）：①**选发的不选熟的**——对 8-12 条题材独有清单逐条掂量后再选，「错配方向是弱页最常见成因」；②**禁止混入默认布局**——"Adopt it. Do not blend it with the layout you would have made anyway"；③**重抽仅限可陈述理由**（品牌冲突/素材缺失，禁因顺手），重抽必记录
- **参照一主一辅**（同源）：视觉参照**一个主参照至多一个辅助**——参照堆叠=混皮肤；参照必须翻译成项目 token/组件规则/Do-Don't 清单后才可用
- **品类同伴研究先行**（oil-ui 1.5k★ 竞品研读 2026-10-24）：动笔前命名产品品类、找 2-3 个**风格最鲜明**的同类、书面决定留什么改什么——同伴是坐标不是模板
- **草稿共享轴 ≤1**（同源）：布局/字排/色彩/关键图像为四轴，**任意两个候选方向至多共享一轴**——共享调色则布局字排图像全须不同；同质草稿 = 假探索
- **分支提示词只给方向**（superdesign 同源）：迭代分支的提示**只说方向，不指定色/风格**——细节由设计判断填充（人管方向，法管细节的分工）；副本/上下文经文件传递不内联
- **同貌结构补救**（同源 squint test 补救法）：眯眼比较后两个方向仍像 → **改布局而非换色**——颜色替换修不了结构性雷同
- **方差律**（soft-skill/classics 交叉 2026-10-22）：多页交付**永不出两个相同布局/气质的连续页**——多页面站点逐页检查布局原型是否轮换（对角/编辑分列/Z 轴层叠/一屏一事轮用），同一 hero 原型连用两页即违律。**网格内也轮换重量**（brandkit 九宫格律 2026-10-22）：面板网格的面板重量轮换（quiet/functional/emotional/technical/atmospheric/detail），等权面板阵=无节奏
- **感受曲线**：叙事页可为每段记录目标情绪及其视觉成因，再选择对应的布局、图像与动效。相邻段持续同一情绪时，复核节奏是否需要变化。
- 选中方向 + 否决原因（逐方向一行）
- 第一直觉（已被处决的默认审美）——书面记录
- **编码前泛化审查**（官方 frontend-design 两遍法 2026-10-22）：token 计划（4-6 个具名 hex/字型角色/ASCII 线框/原则）写完后，**对照简报自问"这计划换成隔壁同行也成立吗？"**——成立即泛，回炉

## §6 · slop 扫描

- 首扫结果 → 修复 → 终扫结果
- warn 豁免论证（如有）
- **截图至上律 + 有界修图循环**（taste-skill inspect/critique 机制 2026-10-22）：门禁过 ≠ 页面好——"Passing the gate means nothing banned was measured. It does not mean the page is good"；**截图里可见的问题就是真的，无论代码怎么说**。交付前目检全部截图，修 top-3 问题 → 复检 → 再目检，**至多三轮**，每轮修了什么记录在此；**修图无像素变化 = 没修**（visual_diff.py 2026-10-24）：每轮修复前后截图跑 `visual_diff.py before.png after.png --min-diff 0.0001`——零像素差即该轮无效（改错文件/改了不可见处/缓存未刷新），三轮循环的每轮有效性由像素差证明
- **大编辑拆分律**（Windsurf 生产纪律 2026-10-23）：单次编辑 **>300 行拆分为多次小编辑**（生成上限意识）——重构不一口吞，按可独立验证的块切
- **根因律**（同源："Address the root cause instead of the symptoms"）：修 bug 优先根因，症状压制须配日志/测试隔离佐证；不确定能解时不动手
- **三击升级律**（Cursor 2.0 生产纪律 2026-10-23，按错误粒度细化三轮循环）：同一文件同一错误**最多修三次**——三次未果即停下换路线或问用户，禁第四次盲目重试（Cursor 原文："DO NOT loop more than 3 times on fixing linter errors on the same file. On the third time, you should stop and ask the user"）；重试前**重读文件**（用户可能已改动——漂移感知的文件级投影）
- **截图-文档同步三查**（XIAS screenshot_docs.mjs 深读 2026-10-24）：README 引用图与磁盘双向对账——**声明缺失**（脚本声明但磁盘无）/**悬空引用**（README 引用但图不存在）/**孤儿图**（磁盘有但无 README 行展示它）三 FAIL；命名=描述性 kebab-case+theme 后缀（dashboard-dark.png）；**确定性拍摄**（固定视口+显式 data-theme+reduce 模拟+**鼠标停泊 2,2 防悬停泄漏**）；--check 只证集合完整不证新鲜度——视觉变更后重拍，"Now LOOK at them before committing"
- **目检带意图**（agent-vision-toolkit 1.2k★ 深读 2026-10-24）：看截图前先写下**这次要看什么**（意图提取→焦点提示）——「检查对比度」的目检与「泛看一眼」产出天差；目检问题清单化（对齐/密度/层级/断点各一问）
- **终检复跑律**（unlazy 4.1k★ --reverify 纪律 2026-10-22）：交付前在**最终工件上全部门禁重跑一遍**——早期 pass 声明不继承（修复过程中门禁状态会漂移）；design-notes 里引用的每个数字来自最后一轮运行
- **对抗式目检律**（XIAS v2.10 /critique 机制 2026-10-22）：**"过门禁永远不是品味的证据"**——目检由未见 maker 推理的批评者执行（分身/子代理只看截图，立场=论证拒绝该交付）；批评者的**召回率用播种缺陷校准**（在过全部门禁的页面里埋已知缺陷，抓不到即批评者失格）。有 visual-judge 类代理时用它替代自评 rubric，无则至少换视角自问"这套页面里哪三处最像模板"
