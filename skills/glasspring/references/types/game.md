# types/game.md — 游戏 UI 类型包（HUD/菜单/竞技/叙事）

> When to read: 游戏 HUD、菜单、轮换界面、结算屏——或任何"信息必须在对局中即时可用"的界面。
> Source status: The historical source ledger is not included in this public preview. Treat this card as project design guidance, not independently verified or universally applicable research.

## 0. 第一决策：这个 UI 属于哪一层？

- **对局内 HUD**（血条/弹药/小地图）→ 信息即生命：半透明度与动画预算近乎为零，字体/描边对比度优先于一切美学。
- **菜单/轮换/结算**（对局外层）→ 玻璃 HUD 的合法主场：Flat 2.0 层次、材质可用、动效预算放宽。
- **叙事/世界观界面**（diegetic：枪身刻度、全息台）→ UI 即道具，风格服务世界观。

## 1. HUD 四件套语法（对局内）

- 四角布局：血/状态（左下）· 弹药/技能（右下）· 小地图（左上）· 目标/计分（顶中）——玩家肌肉记忆跨游戏迁移，勿发明新位置。
- 数字：tabular-nums + 等宽；伤害数字 spring 飘字（唯一高动效许可区）。
- **半透明 HUD 长期覆盖 = CRT/等离子烧屏风险 + 可读性损失**；竞技 HUD 中央区禁透明。
- 红线：关键战斗信息用细字重/低对比；状态色靠色相区分（色盲不可辨）。

## 2. 玻璃 HUD 适用边界（域包实证结论）

**成立**：竞技射击/MOBA 的菜单外层、轮换与结算屏（Flat 2.0 玻璃层次感）；模拟经营全局面板；RPG 对话/背包。
**失败**：恐怖生存（玻璃高光与雾气渲染冲突→diegetic 化）；硬核竞技 HUD 中央常驻区（半透明降低数字可读性=减慢战斗决策）；儿童游戏（认知负荷）。
语法：菜单外层的玻璃层次 + 控制层 chrome（顶部栏/底部 dock）Tier 1 可用；**对局内常驻读数区禁玻璃**。

## 3. 手柄/10 英尺规则（主机移植硬约束）

- XY 焦点导航：焦点框必须无歧义（放大+描边双通道）；**≤6 击穿越屏**；嵌套可交互网格是 d-pad 经典陷阱。
- 尺寸：交互件 ≥32epx、正文 ≥15epx、辅助 ≥12epx；TV 安全区上下 27epx/左右 48epx；TV-safe 色彩 16-235（高饱和溢出）。
- 每屏信息密度 ≈ 手机而非桌面；10 英尺外可读测试必须做。
- 文案：无 tooltip 文化（手柄无 hover）——提示进按键 glyph 图标（A=确认 B=返回 X=... 按平台映射）。

## 4. 风格语法（类型调色板）

| 类型 | 语法要点 |
|---|---|
| 竞技射击/MOBA | 队伍色（蓝/橙）强区分；击杀播报滚动条；伤害数字层级（普通<暴击<击杀） |
| MOBA | 阵营色+稀有度色（白绿蓝紫金装备阶）；技能 CD 扫描；小地图语义 |
| RPG | 稀有度品阶色；对话轮（可跳过/历史回看）；任务日志分主线/支线 |
| 策略 4X | 分国色板在地图底色上可辨；多层级信息下钻（总览→城市→单位） |
| 恐怖生存 | 低饱和单色+噪声纹理；HUD 极简甚至 diegetic（背脊血条式） |
| 儿童 | 大形状高饱和多色；语音引导；无内购诱导暗模式 |

## 5. 质量底线

- 30-60fps 帧预算：UI 动效不得挤占渲染；**常驻 HUD 零 idle 动画**。
- 手柄全流程可完成（设置/商店/无鼠标陷阱）；触屏移植需重构 HUD 密度。
- 玻璃菜单层次须过"截图 3 秒可读"测试（信息位置/层级/对比度）。
