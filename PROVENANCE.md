# Provenance and evidence boundaries

The source was an unversioned local workspace. Its complete private archive and SHA-256 manifest are stored outside the public repository. Public `main` is a sanitized root snapshot; it does not reconstruct development history or prove authorship. Earlier public history is retained in a private archive, and the former audit branch refs are preserved in local recovery bundles.

The source summary was treated as a set of claims. Counts, execution results and file contents were rechecked. Missing historical transcripts, reused labels and reconstructed scores cannot be repaired by inference. Archived variants do not establish independent experiments.

REA comparison used the repository's observed HEAD `41cf869949b82bd0f24d425f6557432ae3a63545`. README, package metadata, MIT license, third-party notices and MCP contracts were retrieved at that revision, with local SHA-256 records. GitHub's unauthenticated REST API returned a rate-limit error; the commit was obtained using `git ls-remote` and the files fetched by that commit.

REA provides investigation tools. Glasspring's source mentions its distribution and explicit uncertainty patterns, but no REA dependency, target investigation trace or installed REA execution was found in the reviewed source. The audit did not run REA. “Inspired by REA” is supported; “powered by REA” and “validated by REA” are not.

The original source ledger includes links to unofficial leaked-prompt collections and speculative model documents. They cannot establish official behavior or license terms. Such references and their claims have been removed from the public adapters. Original research remains in the private baseline. Remaining references require a per-file review before stable release.

A post-publication source scan found internal sample labels and sample-specific observations in the candidate. This cleanup removes the identified labels and observations from the public tree; original tested sample payloads and original before/after screenshots remain excluded. The separate coffee storefront under `examples/coffee-storefront/` is a new fictional illustration inspired by the public pilot brief, not a prior sample result. The palette file named by that brief is absent, so the page uses independent styling and cannot reproduce the planned task. Its local browser captures are stored with the example and must not be presented as Glasspring evaluation evidence. The latest separate sample-suite results are summarized without project identifiers in `PUBLICATION-NOTE.md`.

The coffee example's hero photograph, three-product photograph, and coffee-branch illustration were generated for this example with the built-in image generator on 2026-10-25. Its favicon is an original SVG. The desktop, mobile, and open-bag screenshots were captured from the local static page in Chrome at 1440×1024 and 390×844 CSS-pixel viewports. `examples/coffee-storefront/interaction.gif` is a five-frame GIF of the same fictional page, captured on 2026-10-25 with Playwright 1.53.0 / Chromium 138.0.7204.23 at 1440×1000 CSS pixels, resized to 960×667; the frames show the empty page, adding an item, one item in the bag, quantity two, and the empty bag after removal. These captures contain no real storefront data and use no remote fonts, libraries, or image URLs. The source, asset terms, and broader third-party clearance remain separate review items; this provenance entry does not close the repository's rights gate.

An earlier follow-up removed a set of future-dated claims and several unsupported attributions. The previous statement that remaining guidance was either project advice or linked to an accessible source was too broad. A 2026-10-25 scan still found high-specificity attributions in retained cards—study counts, star counts, and named upstream skill rules—without a claim-by-claim source revision and evidence record. The pinned taste-skill study, for example, distinguishes 248 sites collected, 247 loaded, and 246 re-measured; Glasspring shorthand can obscure those distinctions. Star counts are time-sensitive and are not fixed by a source commit. This does not establish that every attributed rule is false, but it does mean they are not all independently traceable from the current public package. Keep provenance and rights **BLOCKED** until each retained claim is mapped to its source revision or removed/relabelled as project guidance.

No fresh no-skill / with-skill generation experiment was performed by independent hosts during this audit. The retained evaluation protocol explicitly requires new generation, fixed budgets, randomized presentation and outcome-oriented scoring before efficacy claims.
