# Maintainable scope

The useful product is a web-design workflow with evidence tools. The original ambition was a research-to-design system informed by real products. The inspected implementation mostly contains curated prose, token utilities and checks; it lacks a versioned target-capture pipeline that connects REA observations to independently validated design cards.

Keep one entrypoint, routed reference cards, a small set of stable evidence APIs, and a separate development/evaluation layer. The dependency roots worth maintaining are contrast calculation, static scanning, output verification and the browser adapter. The browser adapter's hand-written CDP/WebSocket transport has a different maintenance burden from the numeric utilities; treat it as an optional integration with explicit coverage states.

Retain current tools during audit hardening to preserve reproducibility. Consolidation should follow observed usage, not script counts. A later reduction can move direction dealing, drafting, spring conversion and MCP hosting into optional extras. Do not add frameworks or mandatory services simply to make the project appear more mature.

The immediate subtraction is from claims and distribution: omit dependency trees, internal research, private target projects, unused screenshots, leaked-prompt authority claims, duplicated marketing tables, reconstructed metrics presented as original records, and universal style prohibitions presented as objective quality.

For the intended research workflow, require a small evidence record per design card: target/version, permitted observation scope, capture hashes, observed behavior, inference and uncertainty, adapted principle, discarded alternative, implementation test and retained-source rights. REA may optionally produce investigation evidence; a card must remain inspectable without installing REA. Only add this pipeline after one real authorized target demonstrates a useful closed loop.

The v0 public scope should be responsive web previews and a tested installation path. Native code generation, mini-program runtime support, comprehensive accessibility certification and measurable aesthetic superiority remain outside validated scope.
